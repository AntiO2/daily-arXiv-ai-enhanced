Motivation: MCP服务器封装了面向人类开发者的Web API，其错误消息常指示执行命令、改配置、打开网页或等待，但许多读取这些消息的智能体只能调用服务器工具，二者不匹配导致智能体难以从错误中恢复。

Method: 统计150个常用MCP服务器中3001条错误消息，识别其中指示下一步操作的步骤及其依赖；用五个OpenAI模型在Berkeley Function Calling Leaderboard任务上测试智能体行为；测试两种补救措施：MCP开发者改写错误消息（用服务器工具名替代命令），以及智能体开发者用一句话提示删除步骤。

Result: 3001条消息中949条指示下一步，其中一半依赖服务器无法感知的信息；凭证错误67条步骤中62条要求终端命令/配置/网页，限流30条中20条只要求等待重试。过期凭证场景下终端命令仅使45%任务恢复，损失随模型从GPT-5.5的18分增至GPT-6 Astra的69分；GitHub限流"等待重试"仅6%恢复。MCP侧改写（用登录工具替代命令）将凭证恢复率升至84%，限流恢复率升至88%（重复调用替代空等）；智能体侧一句话提示删除步骤使凭证恢复率达82%。

Conclusion: 错误消息的设计需针对实际读取者：将人类导向的指令改为可调用的服务器工具或调用可重复的调用，由MCP开发者或智能体开发者任一环节修复，均能显著提升智能体的错误恢复能力。

Abstract: Many Model Context Protocol (MCP) servers wrap web APIs built for human developers, and their error messages tell the reader to run a command, edit a configuration, open a web page or wait. Many agents that read them can only call the server's tools. In 150 widely used MCP servers, 949 of 3,001 error messages tell the caller what to do next, and half of these steps depend on something the server cannot see about the caller. On credential errors, 62 of 67 steps ask for a terminal command, a configuration change or a web page; on rate limits, 20 of 30 say to wait and retry without naming the call to repeat. We tested five OpenAI models that act only through the tools of Berkeley Function Calling Leaderboard tasks, and the agents did what the step said. On expired credentials, a terminal command in the step left 45% of tasks recovered, and the loss it caused grew from 18 points for GPT-5.5 to 69 for GPT-6 Astra. On a rate limit, GitHub's "Wait before retrying." left 6%. We tested two remedies. For MCP developers, naming a server tool in the step raised recovery on expired credentials to 84%, with the login tool in place of the command, and on a rate limit to 88%, with the call to repeat in place of the bare wait. For agent developers, deleting the step with a one-sentence prompt before the model reads it raised recovery on expired credentials to 82%.
